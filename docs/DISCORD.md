# Discord Rich Presence

Anilife sets Discord Rich Presence through the official **Discord Embedded App SDK**. A normal
website cannot set presence: Discord only exposes `setActivity()` to an app running inside a
Discord Activity iframe. Opening `anilife.cc` in a browser tab therefore shows the Discord row as
**Inactive** instead of pretending to be linked.

## Application settings

Use the Anilife Discord application:

- Client ID: `1567279187893551185`
- **OAuth2 redirect URI: `https://127.0.0.1`** (a placeholder; the Embedded App SDK performs the real
  Activity redirect, so this exact value is what the official Activity tutorial uses)
- Activity URL mapping: `/` -> `https://anilife.cc`
- Scopes requested at runtime: `identify`, `rpc.activities.write`
- Enable **Activities** and the default **Launch** entry point in the Developer Portal.

If you want the client-secret exchange, also copy the application's Client Secret. If you prefer no
secret, enable **Public Client** in the Discord application's OAuth2 settings; the Worker then uses
the PKCE verifier generated by the Activity.

> A valid client secret is configured as a Wrangler secret for the Anilife application. A fake-code
> probe reaches Discord and returns `invalid_grant`, which confirms the client id, secret and token
> endpoint are accepted.

## Server configuration

The Worker exchanges the Activity authorization code server-side:

```powershell
npx wrangler secret put DISCORD_CLIENT_SECRET
npx wrangler secret put DISCORD_CLIENT_ID   # optional; defaults to 1567279187893551185
npx wrangler deploy
```

The client secret never enters the bundle, a log or Git. `POST /api/discord/token` is rate
limited and only accepts an authorization code; it returns an access token without storing it.
`POST /api/gate/discord` verifies that token with `GET /users/@me` and issues the normal signed
gate cookie, plus the same short-lived gate token in the JSON response. The Activity keeps that
token in memory and sends it as `X-Anilife-Gate` on resolver calls, so playback still works if the
Discord proxy does not persist cookies.

## What is published

- Browsing: `Browsing Anilife` / `Anime streaming`.
- Watching: anime title, `Episode N - SUB|DUB`, poster as the large image, start timestamp.
- The `Show watching anime on Discord status` setting is honoured, and presence clears when the
  Activity closes.

No Discord user token, message content, guild list or friend list is stored or logged.

## Security notes

- `frame-ancestors` allows only `anilife.cc` itself, `discord.com` and `*.discordsays.com`.
- `X-Frame-Options` is not sent because it cannot express an allowlist; the CSP directive is the
  enforced clickjacking control.
- The Discord access token is held in memory only for the Activity session.
- The Worker keeps a fixed `discord.com` upstream, an 8 second timeout and a 16 KiB response cap.
